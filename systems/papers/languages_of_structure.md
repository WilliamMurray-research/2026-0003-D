# Languages of Structure: A Dual‑Layer Architecture for Symbolic and Governance Domain‑Specific Languages

**William Murray**
**9 August 2026**

---

## Abstract

Domain‑specific languages provide formal mechanisms for describing constrained conceptual domains with clarity, determinism, and structural coherence. This paper synthesises two distinct languages developed within a unified systems architecture programme: a minimal symbolic language for environmental state representation and a high‑order governance language for deterministic compiler orchestration. Although these languages operate in different operational contexts, they share a common architectural lineage. Each embodies one half of a dual structure required for coherent systems: symbolic minimalism for local state representation and governance maximalism for global structural regulation. This paper examines the design principles underlying both languages, analyses their complementary roles, and situates them within a broader theory of structured systems.

---

## 1. Introduction

Domain‑specific languages are increasingly used to formalise conceptual domains that benefit from constrained semantics and deterministic interpretation. Their value lies not only in the expressiveness they provide but also in the structural discipline they impose. The two languages examined in this paper were developed for different purposes: one describes environmental state for a rendering system, and the other governs the behaviour of a compiler pipeline. Despite this divergence, both languages reflect a shared architectural principle. They demonstrate how structured systems require two distinct linguistic layers: a symbolic layer that describes local state and a governance layer that regulates global structure.

This paper proceeds in four stages. The first section outlines the theoretical foundations that motivate the dual‑layer architecture. The second examines the symbolic language and its design constraints. The third analyses the governance language and its structural role. The fourth synthesises these findings into a unified account of how the two languages collectively instantiate a general theory of structured systems.

---

## 2. Theoretical Foundations

Structured systems exhibit a consistent pattern across disciplines. They require mechanisms for representing local state and mechanisms for governing global behaviour. These mechanisms are often linguistic in nature, taking the form of symbolic vocabularies and governance grammars. The symbolic layer provides the finite categories through which local dynamics are expressed. The governance layer provides the rules, constraints, and invariants that regulate system‑wide behaviour.

This duality is evident in physical systems, biological regulatory networks, organisational governance structures, and computational architectures. In each case, local dynamics cannot be understood without reference to global constraints, and global constraints cannot operate without a stable vocabulary for local state. The two languages examined in this paper instantiate this duality in a computational context.

## 3. The Symbolic Language

The symbolic language is designed to describe environmental state for a rendering system. Its purpose is to provide a stable semantic contract between an inference engine and any rendering backend. The language is intentionally minimal. It uses finite enumerations, avoids numeric telemetry, and excludes procedural or generative instructions. This minimalism ensures determinism, portability, and long‑term stability.

### 3.1 Design Constraints

The symbolic language adheres to several constraints. It is declarative, describing what is present rather than how it should be rendered. It is deterministic, ensuring that identical input yields identical symbolic output. It is finite, using closed enumerations to avoid ambiguity. It is renderer‑agnostic, enabling both deterministic and generative renderers to interpret the same symbolic document. These constraints reduce cognitive load, simplify implementation, and ensure predictable behaviour across platforms.

### 3.2 Semantic Structure

The language represents environmental state through symbolic categories such as sky mode, solar position, lunar visibility, weather, tide, wind, wave intensity, palette, and daily rhythm. Each category is defined through a small set of enumerated values. The inference engine maps raw telemetry into these categories using deterministic rules. The resulting symbolic document provides a complete description of environmental state without specifying any rendering behaviour.

### 3.3 Functional Role

The symbolic language functions as the local dynamics layer of the system. It provides the vocabulary through which environmental state is expressed. It does not govern system behaviour, enforce constraints across documents, or regulate execution pipelines. Its role is to describe state, not to manage structure.

## 4. The Governance Language

The governance language is designed to orchestrate a deterministic compiler pipeline. It formalises document identity, dependency relationships, phase constraints, semantic attractors, paradigm specifications, runtime semantics, compliance mappings, and lifecycle rules. Unlike the symbolic language, it is intentionally expressive. Its purpose is to regulate global structure rather than describe local state.

### 4.1 Structural Scope

The governance language defines the identity and location of documents, the dependencies between them, and the phase ordering constraints that regulate their relationships. It introduces attractor kernels that function as global semantic anchors. It specifies paradigm semantics that determine how the compiler interprets state, control, evaluation, effects, and invariants. It defines runtime semantics for execution, observability, failure recovery, and deployment. It also provides mechanisms for governance and compliance, including control mappings and evidence requirements.

### 4.2 Deterministic Orchestration

The governance language ensures deterministic behaviour across the compiler pipeline. It defines merge ordering rules that regulate how documents are combined. It enforces invariants that govern semantic interpretation. It provides lifecycle rules that specify how documents evolve or retire. These mechanisms ensure that the system behaves predictably even as its components change over time.

### 4.3 Functional Role

The governance language functions as the global structure layer of the system. It regulates behaviour, enforces constraints, and ensures coherence across documents. It does not describe environmental state or provide symbolic categories. Its role is to govern structure, not to represent state.

## 5. Synthesis: A Dual‑Layer Architecture

The symbolic and governance languages collectively instantiate a dual‑layer architecture for structured systems. The symbolic language provides the finite vocabulary through which local state is expressed. The governance language provides the structural rules through which global behaviour is regulated. Together, they demonstrate how coherent systems require both constrained semantics and expressive governance.

### 5.1 Complementary Roles

The symbolic language ensures clarity, determinism, and stability at the level of local state. The governance language ensures coherence, predictability, and structural integrity at the level of global behaviour. Neither language can fulfil the role of the other. The symbolic language cannot govern structure, and the governance language cannot describe state. Their complementarity is essential to the system’s architecture.

### 5.2 Implications for Systems Design

The dual‑layer architecture illustrated by these languages has broader implications for systems design. It suggests that structured systems benefit from separating state representation from structural governance. It also indicates that minimal symbolic vocabularies and expressive governance grammars can coexist within a single programme. This separation reduces complexity, improves maintainability, and enhances long‑term stability.

---

## 6. Conclusion

The two domain‑specific languages examined in this paper represent distinct but complementary components of a unified systems architecture. The symbolic language provides a minimal vocabulary for describing environmental state, while the governance language provides an expressive grammar for regulating global structure. Together, they illustrate how structured systems require both local semantic clarity and global structural discipline. Their synthesis demonstrates the value of dual‑layer language design and provides a foundation for further exploration of structured systems.
